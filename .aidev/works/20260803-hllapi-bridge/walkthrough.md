# レビューガイド: HLLAPI / EHLLAPI 対応

新規 Rust クレート 1 つ ＋ TypeScript 6 ファイル ＋ テスト 4 本。
**新しい言語が入る PR** なので、どこを見れば「薄さ」が担保されているか分かるように書く。

## 30 秒で分かる要約

既存の HLLAPI 資産（VB / C / Excel VBA）から ts5250 の 5250 セッションを駆動できるようにした。

```
既存資産 ──hllapi(int*,char*,int*,int*)──▶ Rust cdylib ──POST /api/hllapi──▶ TypeScript ──▶ セッション
                                          （C ABI ↔ HTTP だけ）        （機能番号の意味はここ）
```

- **Rust は機能番号の意味を 1 つも知らない。** 対応機能を増やしても DLL の差し替えが要らない。
- **画面は CP932 で返す。** 1 桁 = 1 バイト（全角は 2 バイト）なので、
  既存資産が確保する `24×80 = 1920` バイトの器がそのまま使える。
- **未実装は `rc=10`** で断る（規約にある値）。黙って成功にしない。

## レビューで見てほしい 5 点

### 1. 「薄い」を散文で約束せず、検査に落とした

`packages/server/test/hllapi-bridge-thinness.test.ts` が Rust のソースを走査して、

- HLLAPI の機能名が現れない
- **機能番号で分岐していない**（`match function` / `*func ==`）
- 可変の状態を持たない（`static mut` / `OnceLock` / `Mutex`）
- 外部クレートがゼロ
- **この層が持つ戻り値は 3 つだけ**（サーバーへ届かないときに要るぶん）

を確認する。**一度「1 つだけ機能番号を見る分岐」を許すと次の人が 2 つ目を足す**ので、
機械で止める価値がある。

> この検査を **`cargo test` ではなく `npm test` 側に置いた**のは意図的。
> `cargo test` は標準の検査に含まれず、環境によっては動かない
> （この環境では C コンパイラが無くテスト実行ファイルをリンクできない）。
> **走らない検査は無いのと同じ。**

### 2. なぜ CP932 なのか（**この PR で一番効いている判断**）

HLLAPI の PS は **1 位置 = 1 バイト**。全角は画面で 2 桁を占め、CP932 でもちょうど 2 バイト。

UTF-8 だと日本語 1 文字が 3 バイトになり、**1920 バイトの器に日本語画面が収まらない**
（実機で `rc=6` の切り詰めを踏んだ）。CP932 にしてから `バイト=1920 セル=1920` で一致した。

`hllapi-cp932.ts` は **`TextDecoder('shift_jis')` から逆引き表を組む**ので依存が要らない。
変換表を自前で抱えず、**その環境の復号器と必ず一致する**。

### 3. PS を「文字列」ではなく「バイト配列」で持つ理由

`hllapi-ps.ts` の冒頭。ts5250 は全角を `dbcs-lead` ＋ `dbcs-tail` の 2 セルで持ち、
**追従セルの `char` は空文字**。これを「1 セル 1 文字」で連結すると

```
サイン・オン  →  サ イ ン ・ オ ン       ← 実機の出力で気づいた
```

になり、**日本語で検索できない**。バイトで扱えば `日本` は CP932 の 4 バイトとして素直に見つかる
（実機で `Search PS` が `rc=34` を返すことを確認）。

### 4. 既存の認可を迂回していないか

`hllapi.ts` の `writeIntoField` は **`assertWritable` を先に通す**。
最初これが抜けていて（lint の「未使用引数」で発覚）、**読み取り専用のセッションへ
HLLAPI から書き込めた**。画面や MCP で塞いでいる境界を横から破る形だったので塞いだ。

AID の送信も `assertKeyAllowed` を通す。どちらも回帰テストで固定。

### 5. 安全側に倒したところ

| 箇所 | 判断 |
|---|---|
| 未実装の機能番号 | **`rc=10`**（分岐の既定）。足し忘れても「成功したのに何も起きない」にならない |
| 写せないキー | **1 つでも混ざっていたら何も送らず `rc=20`**。一部だけ送ると画面が半端に残る |
| `Start Host Notification` | **番号を入れていない**。一次資料の目次に誤植があり確定できないため（推測で置かない） |
| バッファ | 容量を超えて書かない。超えたら `rc=6`（切り詰めを黙らない） |
| 待ち | Wait / Pause は最大 30 秒。**無限に待たない** |
| ログ | バッファの中身を出さない（**サインオン画面への入力が通る**） |

## 実機で確かめたこと（SR-OSAKA・日本語画面）

**本物の C ABI**（Python `ctypes` で共有ライブラリを動的リンク）で **25/25**。

```
Copy PS  : バイト=1920 セル=1920（器にそのまま収まる）
画面先頭 : サイン・オン（空白が挟まらない）
Search   : "サイン・オン" → rc=34（日本語で引ける）
Send Key : Enter で画面が変わる（AID が届いている）
未実装   : rc=10 ／ 写せないキー: rc=20 ／ 切断後: rc=8 ／ サーバー不在: rc=9
```

**`Send Key` が「rc=0 なのに画面が変わらない」**と出たときは、セッションを直接見て切り分けた
——サインオン画面が F1/F3 を無視するだけで、Enter なら変わる。**製品側の欠陥ではない**。

## 確かめていないこと（PR で判断してほしい）

- **Windows でビルドも動作確認もしていない。** 実利用者はほぼ Windows なので、
  **最初に確かめるべきはここ**。クレートは OS 非依存（`std::net` のみ）に書いてある。
- **実際の HLLAPI 資産（VB 等）で試していない**（手元に無い）。
- 未実装が 15 機能（Set Session Parameters・Copy OIA・キーストローク傍受・ファイル転送など）。
- 画面を書き換えるローカル操作（Erase EOF・Delete 等）はカーソルを動かすだけ。
